# From this PC to a server, when the time comes

Jungle Book runs **only on this Windows PC and the home Wi-Fi** for now: port 5000, the database in
`C:\Nexus\data\nexus.sqlite`, the media store in `C:\Nexus\data\media`, started by a scheduled task and
kept alive by `tools/local-backend/jungle-backend-service.mjs`. Nothing here needs a tunnel, a domain or a
public address, and none of it is configured.

This page exists so that the later move does not have to be rediscovered. Every setting below is already
read from one place — the environment — and no address, path or secret is written in the sources.

## The one file a deployment changes

`C:\Nexus\env\jungle.env` (template: `tools/local-backend/env.example`, written by
`init-local-backend.mjs`). The service reads it at start; nothing else does.

| Setting | Today | On a hosted server |
| --- | --- | --- |
| `NODE_ENV` | `development` on purpose: the phone reaches the PC as plain HTTP on a trusted LAN, and `production` makes the server refuse every non-TLS request (`lib/api.js`) | `production`, with TLS terminated in front — no exception |
| `NEXUS_DEPLOYMENT_MODE` | `local` | the host's own label; it selects the deployment contract the release checks read |
| `PORT` / `HOST` | `5000` / `0.0.0.0` | whatever the platform injects; bind the loopback and let the proxy listen |
| `NEXUS_DATA_DIR` | `C:\Nexus\data` | a **persistent volume**, mounted at a path the app can write on every restart (a container's own filesystem is lost) |
| `NEXUS_SESSION_SECRET` | generated here, 64 chars, never printed | generated by the platform's secret store; rotating it signs every device out, which is the intended effect |
| `NEXUS_ACCEPTED_ORIGINS` | `http://localhost:5000,http://127.0.0.1:5000,http://192.168.1.153:5000` | the public HTTPS origins only, one per line-value, **no port wildcards** (the NativeAuth SDK reads `*` as a subdomain wildcard and throws on a port wildcard — `lib/mvx.js` now drops such entries with a warning) |
| `GOOGLE_CLIENT_ID` / `SECRET`, `JAMENDO_CLIENT_ID`, `NEXUS_WC_PROJECT_ID` | empty, which disables the provider instead of pretending | the owner's own credentials; an empty value still disables the feature cleanly |
| `NEXUS_REQUEST_LOG` | `1`, one line per request | leave on: it is how the phone's traffic was proven from the server side |

The app side has its own single switch: `apps/nexus-mobile/.env` →
`EXPO_PUBLIC_NEXUS_API_URL`. It is inlined at bundle time, so a change means restarting Metro with
`--clear`. When it is absent, `lib/apiOrigin.ts` uses the host that served the bundle (the PC), and with
neither value it uses the phone's own loopback through `adb reverse tcp:5000`, saying so on the console.
There is no remote fallback: a build that cannot name a backend fails visibly instead of talking to a
server the owner did not choose (`JUNGLE_BOOK_PROGRESS.md` §34.2).

## What has to change besides the environment

1. **TLS.** A tunnel/proxy terminates HTTPS and forwards to the app; the app itself keeps refusing
   non-TLS requests under `NODE_ENV=production`, which is the property that makes the cookie flags
   meaningful. Session cookies then need `Secure` (already decided by `setSessionCookie` from the
   request's scheme).
2. **Storage.** `NEXUS_DATA_DIR` must be a real volume, and the media store a directory that survives a
   redeploy. Media is content-addressed (`<sha256>.<ext>`), so it can also be served from an object
   store or a CDN later without touching a single row: the database only ever holds the hash.
3. **Backups.** Here: `backup-db.mjs` at 03:30 with `VACUUM INTO` snapshots plus a hard-linked media
   copy, and `restore-backup.mjs --drill` to prove them. On a host: the same snapshots uploaded
   off-machine (a bucket), and the same drill run against a downloaded snapshot. The snapshot is a
   single SQLite file, so nothing about it is PC-specific.
4. **The supervisor.** `jungle-backend-service.mjs` (backoff, health probes, cooperative stop) is what
   keeps a *desktop* alive. A platform's own process manager replaces it; the health endpoint it probes
   is `/api/version` and `/health`, both already present and cheap.
5. **The migration tooling.** `tools/migration/*` is a one-way import from the hosted backend. It is not
   part of the product's runtime and does not run on the server; keep it for the record.
6. **Data.** The Railway volume was never exported as a file; the local database is a faithful copy of
   what the API answered, not a byte-for-byte copy of the volume (see `JUNGLE_BOOK_PROGRESS.md`, §18.9:
   one avatar object of a test account was referenced but never exported, and it cannot be recovered
   without the hosted storage). A move performed later must move *this* SQLite file and this media
   directory — they are the truth now.

## What must not be copied blindly

- `C:\Nexus\env\jungle.env` holds a secret. Copy the *shape* (`env.example`), never the value.
- The PC's current LAN address appears in `.env`, `NEXUS_ACCEPTED_ORIGINS` and the phone's bundle — all
  three are configuration, none is source. Moving to a fixed public hostname removes the renewal problem
  this arrangement has (a new DHCP lease means re-running `init-local-backend.mjs` and restarting Metro).
- `NEXUS_DEPLOYMENT_MODE=local` and `NODE_ENV=development` are *deliberate* local choices. A hosted
  deployment that carried them over would either refuse to start or serve plain HTTP.
